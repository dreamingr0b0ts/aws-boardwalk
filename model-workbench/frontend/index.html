Alpenglow Model Workbench

"Which model should we use?" is a procurement question, not a matter of taste. This bench sends one prompt to four foundation models from four vendors, through the single Bedrock Converse API, and lines the answers up with measured latency, token counts, and computed cost. Every run lands in an audit ledger: who ran what, against which models, with which parameters.

CH 01 · Roster

Four channels on the bench

Four models, four vendors, one Converse call. Swapping models on Bedrock is a parameter, not a re-integration. Prices are published on-demand rates per million tokens, embedded so every response can carry its real cost.

CH 02 · Access

Try it now, no sign-in needed

The bench below is live for every visitor: 5 free runs a day from the scenario library, fanned out to all four models. Every run costs real tokens, so the free tier is deliberately small and drawn from a shared daily pool. Signing in raises the limit to 30 runs a day and unlocks custom prompts; the credential is not printed here and there is no self-signup, Planetek hands it out with proposals and demos.

CH 03 · Bench

Run a comparison

Visitor mode: scenario prompts only, 5 free runs a day. Sign in for 30 runs a day and custom prompts.

Every comparison also gets a blind judge: the cheapest roster model scores each answer 1-10 against the scenario's rubric without knowing which model wrote which. The judge call is metered and lands in the ledger like everything else.

Audit ledger: today's runs

Model, parameters, tokens, cost, and latency for every run, including visitor runs (logged by a truncated hash, never an address). That is the accountability trail an agency's AI policy (think SB24-205) actually asks for. Rows expire after 30 days.

Sign in to browse the ledger. Your visitor runs are already in it.

CH 04 · Scenario library

Prompts shaped like real work

The library mirrors the public-sector GenAI work this portfolio exists to win: plan-review triage, grounded code Q&A with a refusal test, determination letters, structured extraction, plain-language rewrites. All fictional, all self-contained.

    CH 06 · Evidence

    What this plank proves

    • Model selection as an engineering discipline: the same prompt, the same parameters, four vendors side by side, with latency, tokens, and cost measured rather than estimated. The "cheapest capable model" conversation becomes evidence-based.
    • One API, any model: Bedrock's Converse API makes the fan-out a loop rather than four integrations. Swapping or adding a model is IAM plus a config entry, which is exactly the exit-ramp a government buyer should demand from a GenAI vendor.
    • Auditable by construction: every run is logged with its parameters, token usage, and computed cost. That is the explainable audit trail responsible-AI policies require, demonstrated rather than promised.
    • Spend that cannot run away: visitors get 5 scenario runs a day (counted by hashed IP) from a small shared pool; custom prompts sit behind a Cognito gate with no self-signup and an unpublished credential. Per-caller and demo-wide daily caps in DynamoDB, a hard output-token ceiling, and a 5 rps edge throttle bound every path. Idle cost is $0, and the free tier draws from the same global daily budget, so opening it raised the worst-case day by nothing.
    • Grounding differences made visible: the refusal-test scenario shows which models admit "the excerpt doesn't say" and which ones confidently invent. For civic AI that is the single most important behavior.
    • Evaluation with criteria, not vibes: every comparison is scored by a blind judge model against the scenario's written rubric (answers shuffled and anonymized so the judge cannot play favorites), and the JSON scenario is additionally graded by plain code: does it parse, does it match the schema. Two different proofs that "which answer is better" can be a measured question.
    • Guardrails you can watch working: flip one switch and the same prompt runs through a Bedrock Guardrail that masks emails, phone numbers, and SSNs and refuses legal-advice requests. Policy enforced in the platform, outside the model's discretion, visible in the answer text.
    • Operations leave a public record: thirty days of runs, median latency, and cost per model, aggregated straight from the audit ledger onto this page. The bench publishes its own track record.
